1. 삭제 대상

경로 판정 사유
gg/gg.db 삭제 사용자 요청. 기존 SQLite 산출물. 새 PostgreSQL `gg_db`(회원 정보 저장용)로 대체.
gg/test_sync.py 삭제 sync(Pull/Push) 컨셉 자체가 폐기되어 테스트 대상 자체가 사라짐.
gg/app/models/product.py 삭제 상품을 우리 DB에 저장하지 않으므로 Product ORM 모델 불필요.
gg/app/routers/sync.py 삭제 POST /sync/from-cafe24, POST /sync/to-cafe24, GET /sync/dirty 모두 폐기. 상품 등록·수정 시 Cafe24와 즉시 동기화하는 흐름으로 대체.
gg/migrations/versions/53009654b6e4_init_products_table.py 삭제 products 테이블 마이그레이션. 상품 테이블 자체가 사라지므로 제거.
gg/migrations/versions/f34616b6e3c9_datetime_timezone_aware.py 삭제 products 컬럼 timezone 변경 마이그레이션. products 제거와 함께 제거.
발표.txt (루트) 검토 프로젝트 코드와 무관한 발표 메모. 사용자 보관용일 가능성 높음 → 삭제 금지, 사용자 확인 후 처리.

2. 재작성 (현 코드 폐기 후 새로 작성)

경로 판정 사유
gg/app/routers/products.py 재작성 현재 GET/POST/PUT/POST(generate-ai)가 모두 로컬 DB를 거친다. Cafe24 직통 CRUD(목록·단건·등록·수정·삭제)로 재작성.
gg/app/services/product_service.py 재작성 현재 코드는 ProductService → DB → Cafe24 흐름. DB 의존성 제거 후 Cafe24 클라이언트로 직접 위임하는 얇은 어댑터로 축소(또는 제거하고 라우터에서 직접 호출).
gg/app/schemas/product.py 재작성 SyncResult, PushResult, is_dirty, is_ai_processed 등 동기화 메타데이터 필드 전부 폐기. Cafe24 송수신용 페이로드와 응답 스키마로 재정의.
gg/app/main.py 재작성 현재 create_db_tables()가 Product 테이블을 자동 생성하는 lifespan을 가지고 있음. users 테이블 마이그레이션은 alembic으로 관리하고 lifespan에서 DDL 자동 생성을 제거. 라우터 등록을 새 라우터(auth, ai, health)로 교체.

3. 검토 필요

경로 판정 사유
gg/app/routers/categories.py 검토 상품 등록 시 카테고리 번호 선택용으로 유용. 다만 현재 코드에는 "로컬 DB 폴백" 분기가 있어 Product 모델 의존성이 존재 → DB 폴백 분기 제거 후 보존하거나, 폴백 자체 삭제 후 보존.
gg/app/schemas/category.py 검토 categories 라우터를 보존한다면 같이 보존. 라우터 자체를 제거한다면 함께 삭제.

4. 보존

경로 판정 사유
gg/app/services/cafe24_client.py 보존 토큰 자동 갱신 + .env 업데이트 로직이 핵심. 추가로 delete_product, upload_image 메서드만 확장.

gg/app/deps.py 보존 get_db는 그대로. get_current_user(JWT 검증) 추가만 하면 됨.
gg/migrations/env.py, script.py.mako 보존 Alembic 인프라. 신규 users 마이그레이션 작성에 그대로 사용.
