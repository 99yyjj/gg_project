[1] 인사 및 소개
----------------------------------------------------------

안녕하세요. 저희 캡스톤 프로젝트 발표를 맡은 OOO입니다.

저희가 만든 프로젝트의 이름은 GG, 부제는
"AI 기반 1인 쇼핑몰 플랫폼"입니다.

요즘은 누구나 마음만 먹으면 카페24, 네이버 스마트스토어 같은
플랫폼으로 혼자서도 쇼핑몰을 운영할 수 있는 시대입니다.
하지만 막상 시작해 보면, 디자인보다 더 막막한 게 바로
'상품 설명을 어떻게 써야 하지?' 라는 부분이었습니다.

그래서 저희는 이 프로젝트에서 1인 사장님이 상품 한 개를
등록할 때, AI가 옆에서 마케팅 문구를 대신 써주고,
카페24와 자동으로 연결까지 해주는 백오피스 플랫폼을
만들어 보았습니다.



[2] 문제
----------------------------------------------------------

저희가 풀고자 했던 문제는 크게 세 가지였습니다.

첫째, "글쓰기에 익숙하지 않은 1인 사장님의 부담"입니다.
상품을 만드는 것보다 그 상품을 매력적으로 설명하는 글을
쓰는 게 훨씬 어렵다는 말이 많습니다. 카피라이터를 따로
고용할 여유는 없고, 그렇다고 매번 다른 사이트에서 베끼는
것도 한계가 있습니다.

둘째, "여러 도구를 오가며 작업해야 하는 비효율"입니다.
보통은 메모장에 문구를 쓰고, 챗GPT에 다시 다듬고,
카페24 관리자 화면에 들어가서 복사 붙여넣기를 합니다.
이 과정이 상품마다 반복되면 시간이 굉장히 많이 듭니다.

셋째, "API 토큰 만료 문제"입니다.
카페24 API의 액세스 토큰은 2시간이면 만료되기 때문에,
기존 도구들은 자주 끊기고 다시 로그인해야 하는 불편이
있었습니다.



[3] 해결
----------------------------------------------------------

저희는 이 세 가지 문제를 다음과 같이 풀었습니다.

첫째 문제, 즉 글쓰기 부담은 'AI 자동 문구 생성' 기능으로
해결했습니다. 사용자는 상품명과 가격만 입력하고, "AI로
채우기" 버튼만 누르면 Gemini가 즉시 마케팅 문구와 분류
태그를 만들어 줍니다. 결과가 마음에 들지 않으면 그 자리에서
바로 수정할 수도 있습니다.

둘째 문제, 작업 동선 비효율은 '카페24 직접 연동'으로
해결했습니다. 저희 화면에서 등록 버튼 한 번이면 그대로
카페24 쇼핑몰에 상품이 올라가고, 수정·삭제도 한 번에
반영됩니다. 우리 데이터베이스에 상품을 따로 저장하지 않고
카페24를 단일 진실 공급원으로 두기 때문에, 데이터가 두
군데에서 엇갈리는 문제도 없습니다.

셋째 문제, 토큰 만료는 '자동 갱신 로직'으로 해결했습니다.
어떤 요청이든 401(인증 만료)이 떨어지면, 시스템이
자동으로 리프레시 토큰을 사용해 새 토큰을 발급받고,
.env 파일까지 새 값으로 덮어쓴 다음, 원래 요청을 다시
실행합니다. 사용자는 끊김 없이 작업을 이어갈 수 있습니다.



[4] 기술 스택과 선택 이유
----------------------------------------------------------

저희가 사용한 주요 기술 스택은 크게 백엔드, 데이터베이스,
프론트엔드, 그리고 AI로 나뉩니다.

먼저 백엔드는 Python의 FastAPI를 선택했습니다.
이유는 세 가지입니다.
첫째, 비동기(async)를 기본으로 지원하기 때문에 카페24 API
같은 외부 호출이 많아도 서버가 멈추지 않습니다.
둘째, Pydantic 기반 자동 문서화로 Swagger UI가 무료로
따라옵니다. 발표나 시연용으로 매우 유용했습니다.
셋째, 한국어 자료와 학습 곡선이 좋아서 1인 개발에도 적합
했습니다.

데이터베이스는 PostgreSQL을 SQLAlchemy 비동기 ORM과
함께 사용했습니다.
SQLite로 시작하는 것도 가능했지만, 다중 사용자가 동시에
접속하는 상황을 가정하면 PostgreSQL이 더 안정적이고,
실제 서비스로 발전시킬 때 그대로 가져갈 수 있다는 점이
컸습니다. 마이그레이션은 Alembic으로 관리해서, 테이블
구조가 바뀌어도 추적과 복구가 가능하게 했습니다.

비밀번호 보안은 bcrypt로 해시해서 저장하고, 인증은 JWT를
사용했습니다. 액세스 토큰은 30분, 리프레시 토큰은 14일로
나누어 보안과 사용자 편의 사이의 균형을 맞췄습니다.

프론트엔드는 Next.js 16과 React 19, TypeScript, Tailwind
CSS를 사용했습니다.
Next.js를 선택한 이유는 App Router 구조 덕분에 페이지를
폴더로 정리할 수 있어 1인 개발이 깔끔해지기 때문이고,
TypeScript는 백엔드 스키마와 프론트 타입을 1:1로 연결해
서로 다른 곳에서 발생하는 버그를 미리 막아 주기 때문입니다.
Tailwind는 디자인에 시간을 너무 쓰지 않으면서도 일관된
UI를 빠르게 만들 수 있다는 장점이 있었습니다.

서버 상태 관리는 TanStack Query, 폼은 React Hook Form +
Zod를 썼습니다. 이 조합 덕분에 새로 고침해도 데이터가
캐시되고, 입력값 검증이 자동으로 되어서 코드가 매우
간결해졌습니다.

마지막으로 AI는 Google Gemini 2.5 Pro를 사용했습니다.
무료 티어가 있고, 한국어 마케팅 문구의 자연스러움이 좋아서
선택했습니다. 또한 Mock 모드를 같이 만들어 두어서, API
키가 없는 환경에서도 데모가 가능하도록 했습니다.



[5] 프로젝트 목표
----------------------------------------------------------

저희가 잡은 목표는 다음 다섯 가지입니다.

첫째, 1인 사장님이 상품을 등록·수정·삭제할 때 가장 적은
클릭으로 카페24까지 한 번에 반영되게 만든다.

둘째, 글을 쓸 줄 모르는 사용자도 AI가 만든 초안을 받아
바로 활용할 수 있게 한다.

셋째, 토큰이나 인증 같은 기술적인 문제가 사용자에게 보이지
않도록 한다.

넷째, 사용자의 회원 정보는 우리 DB에서 안전하게 관리하되,
상품 데이터는 카페24를 단일 진실 공급원으로 두어서
데이터 중복과 동기화 오류를 원천적으로 차단한다.

다섯째, 코드 구조가 명확해서 나중에 다른 팀원이 들어와도
유지보수가 가능하도록 한다.



[6] 시스템 구성
----------------------------------------------------------

저희 시스템은 크게 네 개의 레이어로 구성되어 있습니다.

첫 번째 레이어는 '프론트엔드' 입니다.
Next.js 기반 웹 페이지로, 로그인·회원가입·대시보드·상품 목록
·상품 등록·수정·상세·삭제·내 정보 페이지가 있습니다.
모든 외부 호출은 axios 인스턴스를 통해 백엔드로 보냅니다.

두 번째 레이어는 '백엔드 API 서버' 입니다.
FastAPI로 만든 서버이며, 라우터·서비스·스키마로 책임을
분리했습니다. 라우터는 HTTP 요청을 받고, 서비스는 핵심
로직을 담당하고, 스키마는 입출력 데이터의 형태를 검증합니다.

세 번째 레이어는 '데이터베이스' 입니다.
PostgreSQL에 회원 정보(users 테이블)만 저장하고, 비밀번호는
bcrypt 해시로 보관합니다. 상품 데이터는 저장하지 않습니다.

네 번째 레이어는 '외부 서비스' 입니다.
카페24 어드민 API와 Google Gemini API 두 곳에 연결되어
있으며, 각각 cafe24_client, ai_service라는 모듈을 통해
호출됩니다.

전체 흐름을 한 줄로 설명하면 이렇습니다.
"사용자가 프론트에서 버튼을 누르면, 백엔드가 인증을 확인하고,
필요하면 Gemini로 문구를 만들고, 그 결과를 카페24로 바로
보낸다." 입니다.



[7] 개발한 주요 기능
----------------------------------------------------------

지금부터 저희가 실제로 구현한 기능을 하나씩 보여드리겠습니다.

(1) 회원가입과 로그인
이메일·아이디·비밀번호·실명·전화번호·쇼핑몰 이름을 입력하면
가입이 됩니다. 비밀번호는 bcrypt 해시로 저장되고, 로그인
하면 JWT 액세스 토큰과 리프레시 토큰이 발급됩니다.
더미 사용자 네 명이 미리 들어가 있어서 즉시 시연이 가능
합니다.

(2) 신규 상품 등록
상품명, 가격, 카테고리, 진열 여부 등을 입력하고, "AI로
채우기" 버튼을 누르면 Gemini가 마케팅 문구와 태그를 즉시
만들어 줍니다. 사용자는 결과를 바로 수정할 수 있습니다.
이미지를 업로드하면 카페24 CDN으로 직접 올라가고, 그
경로가 상품에 자동으로 연결됩니다.

(3) 상품 수정
기존 상품을 불러와서 이름, 가격, 문구, 이미지 등을 부분적
으로 바꿀 수 있습니다. 보낸 필드만 업데이트되도록 만들어
놓아서, 다른 정보가 의도치 않게 사라지는 일이 없습니다.

(4) 상품 삭제
목록 또는 상세 화면에서 휴지통 버튼을 누르면 카페24에서
상품이 즉시 삭제됩니다.

(5) 상품 목록·단건 조회
페이지네이션이 적용된 목록과 각 상품의 상세 정보를
보여 줍니다.

(6) AI 마케팅 문구 자동 생성
별도 엔드포인트로 분리되어 있어서, 등록·수정 화면 어디
에서나 호출할 수 있습니다. 톤앤매너를 지정하는 커스텀
프롬프트도 함께 보낼 수 있어서, "20대 여성 타깃, 고급
스럽게" 같은 지시를 줄 수 있습니다.

(7) 액세스 토큰 자동 갱신
가장 중요한 기술적 기능 중 하나입니다.
카페24 API에 요청을 보냈을 때 401이 떨어지면, 시스템이
리프레시 토큰으로 새 토큰을 받아 와서 .env 파일까지
업데이트하고, 원래 요청을 자동으로 다시 실행합니다.
사용자는 이 과정을 전혀 눈치채지 못합니다.

(8) 헬스체크
서버 자체의 상태를 확인하는 기본 헬스체크와, DB 연결까지
확인하는 상세 헬스체크 두 가지가 있습니다. 운영 단계에서
모니터링과 로드밸런서 헬스 프로브에 그대로 활용할 수
있습니다.



[8] 기대 효과
----------------------------------------------------------

이 프로젝트가 실제로 가져다 줄 수 있는 효과는 다음과
같습니다.

첫째, 상품 등록 시간이 줄어듭니다.
기존에 한 상품에 10~20분 걸리던 작업이 1~2분 안에
끝납니다.

둘째, 마케팅 글쓰기에 대한 심리적 장벽이 사라집니다.
"잘 써야 한다"는 부담 대신, "AI가 쓴 초안을 다듬는다"는
관점으로 바뀌어서 등록을 미루는 일이 줄어듭니다.

셋째, 데이터 정합성이 올라갑니다.
카페24가 단일 진실 공급원이기 때문에, 화면에 보이는 정보가
곧 쇼핑몰에 노출되는 정보입니다. 두 곳의 데이터가 어긋나는
문제가 원천적으로 사라집니다.

넷째, 1인 사장님이 본업에 집중할 수 있습니다.
좋은 상품을 만들거나, 사진을 찍거나, 고객 응대에 더 많은
시간을 쓸 수 있게 됩니다.

다섯째, 보안이 강화됩니다.
비밀번호는 평문으로 어디에도 남지 않고, 카페24 토큰은
사용자 눈에 보이지 않으면서도 자동으로 관리됩니다.



[9] 활용 방안
----------------------------------------------------------

저희는 이 프로젝트가 다음과 같은 방향으로 확장될 수 있다고
생각합니다.

첫째, "1인 셀러용 SaaS"로의 발전입니다.
지금은 한 사장님 한 카페24 계정만 다루지만, 사용자별로
카페24 mall_id와 OAuth 토큰을 따로 보관하면 여러 사장님이
한 플랫폼에서 자기 쇼핑몰을 관리할 수 있습니다.

둘째, "AI 기능의 확장"입니다.
지금은 마케팅 문구와 태그만 만들지만, 같은 구조에서 상품
이미지의 배경 제거, 썸네일 자동 보정, 키워드 광고 문구
생성, 경쟁 상품 분석 같은 기능도 추가할 수 있습니다.

셋째, "다른 쇼핑몰 플랫폼으로의 확장"입니다.
지금의 cafe24_client 모듈은 외부 API와의 통신을 한 곳에
모아 두었기 때문에, 같은 구조의 naver_client, coupang_client
모듈을 추가하면 멀티 채널 셀러 도구로 발전할 수 있습니다.

넷째, "데이터 분석 대시보드"입니다.
카페24 주문 API와 연동하면 매출 추이, 잘 팔리는 상품, AI
문구가 매출에 미친 영향 같은 분석을 함께 볼 수 있습니다.

다섯째, "교육 자료로의 활용"입니다.
저희 코드베이스 자체가 FastAPI + Next.js + 외부 API 연동
+ AI 호출 + JWT 인증을 한 번에 보여주는 학습 예제이므로,
후배들의 캡스톤 출발점으로도 좋은 자료가 될 수 있습니다.



[10] 마무리
----------------------------------------------------------

지금까지 GG, 'AI 기반 1인 쇼핑몰 플랫폼' 프로젝트를
소개해 드렸습니다.

저희가 이번 캡스톤을 통해 배운 가장 중요한 점은,
"기술이 화려한 것보다 사용자의 실제 동선을 줄이는 것이
훨씬 가치 있다"는 사실이었습니다.

상품 하나 등록하는 데 필요한 클릭을 절반으로 줄이고,

==========================================================
  발표 도중 시연 순서 (참고용 메모)

1) 백엔드 가동 확인
   터미널: uvicorn app.main:app --reload
   브라우저: http://127.0.0.1:8000/docs (Swagger UI 노출)

2) 프론트 가동
   터미널: npm run dev
   브라우저: http://localhost:3000

3) 로그인 시연
   아이디: daily_lee / 비밀번호: Test1234!
   → 대시보드 진입

4) 신규 상품 등록 시연
   상품명: "봄 데일리 셔츠" / 가격: 19900
   → "AI로 채우기" 클릭 → 문구 자동 생성
   → "Cafe24에 등록" → 카페24 어드민에서 결과 확인

5) 토큰 자동 갱신 시연 (옵션)
   .env의 CAFE24_ACCESS_TOKEN을 일부러 망가뜨린 뒤
   상품 목록 새로고침 → 시스템이 자동으로 새 토큰을
   받아오는 로그가 콘솔에 찍히는 것을 보여줌

6) 상품 수정·삭제 시연
   목록에서 방금 등록한 상품 → 수정 → 다시 카페24에 반영

7) 마무리 인사
